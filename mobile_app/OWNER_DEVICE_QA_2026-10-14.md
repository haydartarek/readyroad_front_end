## 1. Android عبر USB — تجربة التطوير المحلية

المتطلبات: Android SDK platform 36 وplatform-tools وbuild-tools المناسبة وNDK **28.2.13676358** لنسخة Flutter المثبتة، Java الملائم، ورخص SDK مقبولة. الحد الأدنى الحالي **Android 7 / API 24** من إعداد Flutter. لا تغيير لمعرف التطبيق القائم.

المسار المسجل حاليًا في `android/local.properties` يشير إلى `/opt/android-sdk-linux` غير الموجود على Windows. بعد تثبيت SDK، عيّن **المسار الحقيقي** بواسطة `flutter config --android-sdk` أو إعداد Flutter/Android Studio، ثم راجع `flutter doctor -v`. فحصنا لا يثبت أو يغير SDK تلقائيًا.

شغّل خدمات Rijvia بالسكريبت القائم `run-local.ps1 -NoMobile`، ثم صِل Android مع USB debugging ووافق على الجهاز. من PowerShell:

```powershell
Set-Location -LiteralPath 'C:\Users\haydar\Desktop\end_project\readyroad_front_end\mobile_app'
flutter devices
$RijviaDeviceId = Read-Host 'Android device ID from flutter devices'
# adb يجب أن يكون من platform-tools المثبتة؛ إعادة توجيه للتطوير عبر USB فقط.
adb -s $RijviaDeviceId reverse tcp:8890 tcp:8890
if ($LASTEXITCODE -ne 0) { throw 'ADB reverse failed' }
flutter run -d $RijviaDeviceId --dart-define=API_BASE_URL=http://127.0.0.1:8890
```

عنوان HTTP محلي خاص بتجربة debug عبر USB. إصدار release يتطلب HTTPS فعليًا. إزالة توجيه USB بعد التجربة اختياريًا: `adb -s $RijviaDeviceId reverse --remove tcp:8890`.

## 2. فحص مدخلات الإصدار دون بناء أو نشر

ضمن السكريبت الموحد نفسه؛ هذا الوضع لا يشغّل المجموعة الكاملة أو خدمات أو اتصالات إنتاج:

```powershell
$RijviaApprovedApi = Read-Host 'Approved HTTPS API base URL'
& .\validate-local.ps1 -StorePreflightOnly -ApiBaseUrl $RijviaApprovedApi
```

يمكن تمرير `-AndroidSdkPath` بمسار SDK حقيقي لفحصه فقط؛ لا يعدّل إعداد Flutter. السكريبت يبلّغ عن وجود التوقيع دون طباعة القيم أو قراءة محتوى المفتاح. يوقف الفحص عند نقص المتطلبات. حتى `STORE_LOCAL_INPUTS=PASS` ليس اعتماد حزمة أو تصريح نشر.

أسماء متغيرات التوقيع موثقة في تقرير الجاهزية؛ اضبطها محليًا بواسطة وسيلتك الآمنة، ولا ترسل كلمات المرور أو المفتاح في المحادثة. بناء AAB الموقّع وفحص 16 KB والتثبيت من Play internal testing خطوات لاحقة؛ لم تُنفذ ولم تُرفع حزمة.

## 3. iOS على Mac

يلزم Mac وXcode 26+ وSDK iOS 26+ وApple Team/provisioning مناسب للحزمة القائمة. افتح `ios/Runner.xcworkspace` بعد تجهيز تبعيات Flutter/iOS، ثم اختر الفريق والجهاز الحقيقي. حد النشر الحالي iOS 13؛ بيئة Windows الحالية لم تبنِ archive.

على Mac، استعمل نسخة المصدر نفسها و`flutter devices` و`flutter run -d <معرف الجهاز>` مع `--dart-define=API_BASE_URL=<عنوان HTTPS المعتمد>`؛ استبدل المواضع بقيمك الحقيقية. لا يعمل localhost الخاص بجهاز Windows تلقائيًا على iPhone. اختبر على iPhone وiPad، ثم راجع تقرير Privacy Manifest المجمع وValidate App قبل أي رفع لاحق.
